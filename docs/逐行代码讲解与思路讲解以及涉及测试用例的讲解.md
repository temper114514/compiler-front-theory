# 逐行代码讲解、思路讲解与测试用例说明

本文档面向“函数、结构体、数组”这三部分，目标不是只说“做了什么”，而是把“代码怎么走、为什么这样做、用哪些测试验证”讲清楚，方便汇报和答辩。

## 1. 先看整体链路

这部分功能的完整链路是：

```text
源码
-> 词法分析得到 token
-> 语法分析归约成语法树
-> 语义回调登记函数/结构体/变量
-> 命令翻译器把结构体、数组、函数翻译成中间命令
-> 测试输出报告验证结果
```

所以，函数和结构体绝不是“只改文法”：
- 文法负责“识别长什么样”
- 语义负责“这东西对不对”
- 命令翻译负责“最后怎么生成中间代码”

### 1.1 一次测试的真实执行顺序

如果按程序实际运行来讲，顺序应该是：

1. `ProgramSyntaxTestRunner.run()` 扫描 `program-tests` 目录，找到测试文件。
2. `executeSemanticTest(...)` 读取源码，创建词法分析器、语法分析表和回调注册表。
3. `ShiftReducePhaserImpl.phase(...)` 开始执行 `shift-reduce` 分析。
4. 每次 `shift` 时，token 先进入 token translator。
5. 每次 `reduce` 时，对应的语义回调和命令翻译器立刻处理当前归约节点。
6. 函数、结构体、数组相关节点在各自的 callback / translator 中完成登记、检查和命令生成。
7. `SemanticResultCallback` 在接受前把入口命令、函数命令段、结构体表、变量表一起打包成结果。
8. `ProgramSyntaxTestRunner.writeReport(...)` 把结果写入 `run-reports/program-syntax/.../*.md`。

你讲的时候可以直接串成一句话：
> 先跑测试入口，再做词法和语法分析；分析过程中每次归约都会触发语义检查和命令翻译；函数体单独收集成函数段，结构体和数组在翻译时变成对象创建、偏移访问和下标访问命令；最后统一写进报告。

### 1.2 结构体和数组在命令链里的位置

为了不漏掉关键实现，这里把两个最容易被忽略的翻译器单独点出来：

- `NewStructTranslator`：处理 `new StructName()`，先查结构体表，再生成结构体实例化命令。
- `NewArrayTranslator`：处理 `new Type[dim]...[dim]`，先检查元素类型和维度，再生成数组创建命令。

这两个翻译器的共同点是：
- 都不是“看见关键字就吐命令”
- 都要先经过语义检查
- 都要依赖前面已经建立好的类型/结构体信息

所以它们在执行链里属于：

```text
语法归约出 new_struct_expr / new_array_expr
-> 对应 translator 做类型检查和对象检查
-> 生成 newStruct / newArray 中间命令
```

### 1.3 函数、结构体、数组的文法怎么规定

这一部分是整个语言规则的“入口约束”，先把能写什么定下来。

函数相关文法：
- `function_decl ::= function_head block`
- `function_head ::= type id ( param_list ) | void id ( param_list )`
- `param_list ::= params | 蔚`
- `params ::= params , param | param`
- `param ::= type id`

这表示：
- 函数必须有函数头和函数体
- 返回类型可以是普通类型，也可以是 `void`
- 参数可空，可多个
- 参数必须是“类型 + 名字”

结构体相关文法：
- `struct_decl ::= struct id { struct_field_list }`
- `struct_field_list ::= struct_fields | 蔚`
- `struct_fields ::= struct_fields struct_field | struct_field`
- `struct_field ::= type id ;`

这表示：
- 结构体必须顶层声明
- 字段列表可空，但字段一旦存在就必须有类型和名字
- 字段后必须有分号

数组相关文法：
- `type ::= type [ ] | type_identifier | boolean | character | int32 | float64 | string`
- `new_array_expr ::= new array_creation_base array_creation_dims`
- `array_creation_base ::= type_identifier | boolean | character | int32 | float64 | string`
- `array_creation_dims ::= array_creation_dims array_creation_dim | array_creation_dim`
- `array_creation_dim ::= [ bool ] | [ ]`
- `loc ::= loc [ bool ] | loc . id | id`

这表示：
- 数组类型由元素类型和维度组成，长度不属于类型
- 数组创建时才给长度
- 可以留空尾维度，支持锯齿数组
- `loc` 同时支持变量、数组下标、成员访问，所以它既能取值，也能当左值

函数调用和结构体实例化：
- `call_expr ::= id ( arg_list )`
- `arg_list ::= args | 蔚`
- `args ::= args , bool | bool`
- `new_struct_expr ::= new type_identifier ( )`

这表示：
- 函数调用必须带函数名和参数表
- 实参按顺序写
- 结构体实例化必须写明结构体类型，不能用 `new()`

## 2. 函数部分逐行讲解

### 2.1 `FunctionSemanticCallback`

文件：[`FunctionSemanticCallback.java`](../src/main/java/org/harvey/vie/theory/semantic/function/FunctionSemanticCallback.java)

这个类的职责是：在 `shift-reduce` 归约过程中，对函数头、return、调用进行语义检查。

核心思路：
- 函数定义先登记到函数表
- return 要检查返回值类型
- 函数调用要检查是否已声明

### 2.1.1 `onReduce`

关键逻辑是：

```java
public void onReduce(ShiftReduceSemanticContext context, SimpleGrammarProduction production) {
    onReduce0(context, normalizeKey(production.toString().trim()));
    ShiftReduceCallback.super.onReduce(context, production);
}
```

逐行讲：
- `onReduce(...)`：每次语法归约都会进来一次。
- `onReduce0(...)`：先执行我们自己的函数语义逻辑。
- `ShiftReduceCallback.super.onReduce(...)`：再保留框架默认流程，不破坏原有回调链。

讲解时可以说：
> 这里不是“扫一遍树后统一检查”，而是“每次归约到对应节点时立刻做检查”，这样函数头、return、调用都能在它们刚形成时就被处理。

### 2.1.2 `prepareFunction`

它负责把函数头登记进函数表。

关键步骤：
- 取函数名 token
- 检查是否重名
- 解析返回类型
- 收集参数表
- 生成 `FunctionRecord`
- 注册到 `FunctionContext`
- 标记当前函数进入函数体

可直接这样讲：
> 函数声明不是只记录一个名字，而是要形成完整签名：函数名、返回类型、参数列表、语法头节点。后面函数调用和 return 检查都依赖这条记录。

### 2.1.3 `collectParameters`

这个方法把参数链表展开成参数对象列表。

它做了几件事：
- 读参数类型
- 拿参数名 token
- 禁止 `void` 做参数类型
- 检查重名参数
- 生成 `FunctionParameter`

讲解时可以说：
> 参数表不是字符串拼起来的，而是每个参数都转成结构化对象，这样后面检查类型和调用参数时才不会丢信息。

### 2.1.4 `validateReturnValue` / `validateCall`

return 和 call 分别检查：
- return 的表达式类型是否匹配函数返回值
- 调用函数是否存在、参数是否可匹配

可以这样总结：
> return 检查解决“函数内部写得对不对”，call 检查解决“函数外部用得对不对”。

补一句更完整的话：
> `FunctionSemanticCallback` 负责单个 return 和 call 的局部语义，而 `FunctionReturnFlowAnalyzer` 负责整个函数体的全局返回路径检查。两者不是重复，而是一个管“点”，一个管“面”。

### 2.1.5 `FunctionReturnFlowAnalyzer`

文件：[`FunctionReturnFlowAnalyzer.java`](../src/main/java/org/harvey/vie/theory/semantic/function/FunctionReturnFlowAnalyzer.java)

这个类负责的是另一件事：**不看单个 `return`，而是看整个函数体是否在所有可达路径上都能返回**。

它的调用关系是：
- `FunctionManager.guaranteesReturn(...)` 会转调它
- `IdentifierScopeCallback` 在函数结束时会用它判断非 `void` 函数是否缺少返回

核心代码思路是：
```java
rules = new ProductionTagStrategy<>(never)
        .when(block, ProgramSemanticTag.BLOCK, ProgramSemanticTag.COMMAND)
        .when(never, ProgramSemanticTag.BLOCK, ProgramSemanticTag.LIST, ProgramSemanticTag.EMPTY)
        .when(blockItemsSequence, ProgramSemanticTag.BLOCK, ProgramSemanticTag.LIST, ProgramSemanticTag.SEQUENCE)
        .when(forward, ProgramSemanticTag.FORWARD)
        .when(returnRule, ProgramSemanticTag.RETURN)
        .when(matchIf, ProgramSemanticTag.CONDITIONAL, ProgramSemanticTag.ELSE_BRANCH);
```

逐行讲：
- `ProductionTagStrategy`：不是写死在某个产生式上，而是按语义标签分发判断规则。
- `block`：判断代码块内部是否保证返回。
- `blockItemsSequence`：如果前半段已经保证返回，后半段就不需要继续补。
- `forward`：递归向子节点查找是否存在返回路径。
- `returnRule`：单独的 `return` 当然保证返回。
- `matchIf`：带 `else` 的条件分支要看两边是否都保证返回，或者条件本身能被常量折叠后只看一边。

它还会看条件是否是常量：
```java
Boolean condition = constantBoolean(context, head.get(2));
```

这表示：
- 如果 `if (true)`，只看 then 分支
- 如果 `if (false)`，只看 else 分支
- 如果条件不是常量，就必须 then/else 两边都能返回，才算整个分支保证返回

讲给老师时可以直接说：
> 这个类不是判断某个 return 合不合法，而是判断函数体是不是“所有路径都有返回”。比如 `if (x > 0) return x;` 这种，虽然里面有 return，但并不意味着整个函数一定返回，所以非 void 函数还是会被判缺少返回。

## 3. 函数命令生成逐行讲解

### 3.1 `FunctionDefinitionTranslator`

文件：[`FunctionDefinitionTranslator.java`](../src/main/java/org/harvey/vie/theory/semantic/command/translator/command/FunctionDefinitionTranslator.java)

它的职责不是直接往主命令流里塞命令，而是把函数体单独存成一个命令段。

关键代码：

```java
if (children.length != 2) {
    throw new CompilerException("function definition requires function head and block.");
}
FunctionRecord function = function(context);
List<SemanticCommand> commands = CommandSegmentSupport.flatten(children[1]);
context.registerFunctionCommandSegment(new FunctionCommandSegment(function, commands));
return new PlaceholderNodeRegister();
```

逐行讲：
- `children.length != 2`：函数定义必须是“函数头 + 函数体”。
- `function(context)`：从当前归约头里找出对应函数记录。
- `flatten(children[1])`：把函数体里的命令压平成线性命令列表。
- `registerFunctionCommandSegment(...)`：把函数体单独挂到函数段里。
- `PlaceholderNodeRegister()`：函数定义本身不直接产生命令流节点。

讲解时可以说：
> 函数体不是全局主命令流的一部分，而是单独保存，最后报告时按函数段输出，这样更符合“入口代码 + 函数代码”分离的结构。

### 3.2 `FunctionCallTranslator`

文件：[`FunctionCallTranslator.java`](../src/main/java/org/harvey/vie/theory/semantic/command/translator/command/FunctionCallTranslator.java)

关键代码：

```java
CommandNodeBuilder builder = new CommandNodeListBuilder();
FunctionRecord record = function(context);
children[2].register(builder);
builder.add(new TerminalNode(context.getCommandFactory().callFunction(record)));
return new NormalCommandNodeRegister(builder.build(), production, children);
```

逐行讲：
- 先建一个命令构建器。
- `function(context)`：拿到调用目标函数。
- `children[2].register(builder)`：先把实参求值命令加入。
- `callFunction(record)`：再发出调用命令。
- 返回新的命令注册节点。

讲解重点：
> 实参一定要先计算，再发 call。这样调用方看到的参数顺序和源码一致，不会乱。

### 3.3 `FunctionReturnTranslator`

文件：[`FunctionReturnTranslator.java`](../src/main/java/org/harvey/vie/theory/semantic/command/translator/command/FunctionReturnTranslator.java)

关键代码：

```java
boolean hasValue = production.containsTag(ProgramSemanticTag.VALUE);
if (hasValue && ConstantAttributes.childIsConstant(context, 1)) {
    ConstantValue value = ConstantAttributes.child(context, 1);
    if (value != null) {
        builder.add(new TerminalNode(context.getCommandFactory().loadConstant(value)));
    }
} else if (hasValue) {
    children[1].register(builder);
}
builder.add(new TerminalNode(context.getCommandFactory().returnCommand()));
```

逐行讲：
- `hasValue`：判断当前 return 是不是带返回值。
- 如果返回值是常量，直接装载常量。
- 否则先生成表达式命令。
- 最后统一追加 `return`。

可以这样讲：
> 这里做了一个小优化：如果 return 后面本身就是常量，就不需要再生成一段复杂表达式命令，直接装载常量即可。

## 4. 结构体部分逐行讲解

### 4.1 `StructSemanticCallback`

文件：[`StructSemanticCallback.java`](../src/main/java/org/harvey/vie/theory/semantic/structure/StructSemanticCallback.java)

这个类负责结构体声明、字段收集、字段偏移分配。

关键代码：

```java
if (context.existStruct(nameToken)) {
    SemanticDiagnostics.reject(context, nameToken, "duplicate struct declaration is not allowed.");
}
List<StructField> fields = collectFields(context, head.get(3).toHead());
StructRecord record = new StructRecord(context.structTableSize(), nameToken, fields, head);
context.registerStruct(record);
```

逐行讲：
- 先查重，避免重复定义结构体。
- `collectFields(...)`：把字段列表展开成真正的字段对象。
- `StructRecord(...)`：生成结构体记录，包含表号、名字、字段表、语法头。
- `registerStruct(...)`：登记到结构体上下文中。

### 4.2 `collectFields`

它的职责是给字段收集并分配偏移量。

关键逻辑：
- 读取字段类型
- 禁止 `void`
- 检查字段重名
- `offset++` 递增分配字段偏移

讲解时可以说：
> 结构体字段不是只保存名字，而是会在语义阶段绑定类型和偏移量。后面成员访问 `obj.x` 不再靠名字查，而是靠固定偏移访问。

### 4.3 `NewStructTranslator`

文件：[`NewStructTranslator.java`](../src/main/java/org/harvey/vie/theory/semantic/command/translator/command/NewStructTranslator.java)

关键代码：

```java
SourceToken nameToken = head.get(1).toToken().getSource();
StructRecord record = context.getStruct(nameToken);
if (record == null) {
    SemanticDiagnostics.reject(context, nameToken, "struct type is not declared.");
}
CommandNode node = new TerminalNode(context.getCommandFactory().newStruct(record));
```

逐行讲：
- 从 `new StructName()` 里拿结构体名。
- 去结构体表查定义。
- 查不到就报错。
- 查到后生成 `newStruct` 命令。

讲解重点：
> 结构体实例化必须依赖已登记的结构体表，不是看到 `new` 就直接生成命令。

### 4.4 `MemberAccessTranslator`

文件：[`MemberAccessTranslator.java`](../src/main/java/org/harvey/vie/theory/semantic/command/translator/command/MemberAccessTranslator.java)

关键代码：

```java
children[0].register(builder);
SemanticType baseType = TypeAttributes.childType(context, 0);
StructRecord struct = context.getStruct(baseType);
StructField field = struct.field(TypeAttributes.childAnchor(context, 2));
builder.add(new TerminalNode(context.getCommandFactory().biasFromStTopToRef(
        CommandDataType.forStorage(field.getType()),
        field.getOffset()
)));
```

逐行讲：
- 先把左操作数的命令压入。
- `baseType`：拿左侧对象的类型。
- 通过类型找到结构体定义。
- 再按字段 token 找字段。
- 最后生成“基址 + 偏移”的访问命令。

讲解时可以说：
> 成员访问不是字符串查找，而是“对象引用 + 偏移量访问”。这也是结构体字段能稳定工作的关键。

## 5. 数组部分逐行讲解

### 5.1 `NewArrayTranslator`

文件：[`NewArrayTranslator.java`](../src/main/java/org/harvey/vie/theory/semantic/command/translator/command/NewArrayTranslator.java)

关键代码：

```java
SemanticType type = TypeAttributes.childType(context, 1);
SemanticDiagnostics.requireNotVoid(context, type, TypeAttributes.childAnchor(context, 1), "void cannot be used as array element type.");
ArrayCreationDimensions.Summary summary = ArrayCreationDimensions.summarizeAndValidate(context, head.get(2));
children[2].register(builder);
builder.add(new TerminalNode(context.getCommandFactory().newArray(
        CommandDataType.forStorage(type),
        summary.getTotalDimensions(),
        summary.getSpecifiedDimensions()
)));
```

逐行讲：
- 先拿数组元素类型。
- 禁止 `void` 做元素类型。
- 汇总并检查数组维度。
- 把每一维长度表达式先算出来。
- 最后生成 `newArray` 命令。

讲解重点：
> 数组类型由基础元素类型和维度共同决定，长度不写进类型里。长度只是创建时的参数，所以锯齿数组才有实现空间。

### 5.2 `ArrayAtExpressionTranslator`

文件：[`ArrayAtExpressionTranslator.java`](../src/main/java/org/harvey/vie/theory/semantic/command/translator/command/ArrayAtExpressionTranslator.java)

关键代码：

```java
children[0].register(thisBuilder);
children[2].register(thisBuilder);
SemanticType baseType = TypeAttributes.childType(context, 0);
SemanticType indexType = TypeAttributes.childType(context, 2);
if (!baseType.isArray()) {
    SemanticDiagnostics.reject(context, TypeAttributes.childAnchor(context, 1), "subscript operator requires an array operand.");
}
if (!SemanticType.scalar(SemanticType.Kind.INT32).equals(indexType)) {
    SemanticDiagnostics.reject(context, TypeAttributes.childAnchor(context, 1), "array index must be int32.");
}
SemanticType resultType = baseType.arrayElementType();
thisBuilder.add(new TerminalNode(context.getCommandFactory().biasFromStTopToRef(
        CommandDataType.forStorage(resultType)
)));
```

对应文法：
- `loc ::= loc [ bool ] | loc . id | id`

这说明数组访问不是单独一类表达式，而是 `loc` 的一种继续扩展方式。也就是说，`arr[i]` 不是“生成一个新对象”，而是“在原来的可访问位置上继续偏移”。

逐行讲：
- `children[0].register(thisBuilder);`
- 先把左边数组对象翻译进命令流。
- `children[2].register(thisBuilder);`
- 再把下标表达式翻译进命令流。
- `SemanticType baseType = TypeAttributes.childType(context, 0);`
- 读取左侧类型，确认它真的是数组。
- `SemanticType indexType = TypeAttributes.childType(context, 2);`
- 读取下标类型，确认它可用于数组访问。
- `if (!baseType.isArray())`
- 左边不是数组就报错。
- `if (!SemanticType.scalar(SemanticType.Kind.INT32).equals(indexType))`
- 下标不是 `int32` 就报错。
- `SemanticType resultType = baseType.arrayElementType();`
- 数组访问一次后，类型降一层，得到元素类型。
- `biasFromStTopToRef(...)`
- 生成“从数组引用按栈顶下标偏移到元素引用”的命令。

讲解时可以说：
> `arr[i]` 在命令层不是普通值，而是一个可继续参与赋值的访问位置，所以它会保留成引用偏移形式。  
> 这样它既能出现在右边取值，也能出现在左边赋值。

为什么不能直接变成普通值：
- 因为左值位置和右值位置不能混。
- 如果这里直接折成值，后续 `arr[i] = x` 就没法继续沿着同一个访问链路写回去了。
- 现在的做法是先保留引用位置，真正读值或写值由后续命令决定。

你在答辩里可以顺着这条线讲：
1. 文法先把 `loc` 分成普通标识符、成员访问和数组访问。
2. 语义阶段确认左边是数组、下标是 `int32`。
3. 命令生成阶段把它翻译成“偏移到元素引用”。
4. 后面的赋值语句再根据这个引用位置决定是读还是写。

和测试的关系：
- `text49-nested-struct-array-lvalue-assignment` 会用到数组下标作为左值链条的一部分。
- `text50-function-nested-struct-array-params` 会把数组访问和函数调用一起串起来，验证这条链路不会断。

## 6. 控制流相关补充

虽然这部分不是你主要负责的核心，但它和函数/结构体/数组的命令生成一起工作。

### `IfStatementTranslator` / `IfElseStatementTranslator`
- 先判断条件是否常量
- 常量就直接裁剪分支
- 非常量就生成标签和 `ifn_goto`

### `WhileStatementTranslator`
- 生成循环入口标签
- 条件为假跳到出口
- 循环体里未决的 `break/continue` 会被绑定到真实标签

### `DoWhileStatementTranslator`
- 先执行一次循环体
- 再检查条件
- 如果条件恒假，也保留一次循环体执行

讲解时可以说：
> 这里的关键不是“有没有 if/while”，而是条件、标签、break/continue 这三者如何在命令层正确闭合。

## 8. 汇报时介绍我的工作

这一部分不要只说“我完成了函数、结构体、数组”，这样太空。汇报时应该按“我负责的范围是什么、每一块具体做了什么、结果怎么体现”来讲。

可以这样开头：

> 我负责的是语义分析后半部分中和函数、结构体、数组有关的功能。  
> 这部分工作不是只增加文法，而是从语法结构识别、语义信息登记、类型检查，到中间命令生成和测试报告输出，形成一条完整链路。

### 8.1 函数部分怎么介绍

函数部分可以分成三层讲。

第一层是函数定义：
- 我支持了函数头和函数体的区分。
- 函数头里会记录返回类型、函数名和参数列表。
- 函数体不会混进全局入口命令流，而是单独形成函数命令段。

第二层是函数语义检查：
- 函数调用时要检查函数是否已经声明。
- 实参数量要和形参数量一致。
- 实参类型要能匹配形参类型。
- 非 `void` 函数要检查是否有合法返回。
- `void` 函数不能返回具体值。
- `return` 不能出现在函数外。

第三层是函数命令生成：
- 函数调用会先生成实参求值命令，再生成 `call` 命令。
- 函数返回会先生成返回值表达式命令，再生成 `return` 命令。
- 函数定义本身不会直接插进全局代码，而是进入独立的 Function Segment。

可以直接举 `text50`：

```text
boolean readStudentArray(Student[] students, int32 index) {
    return readStudent(students[index]);
}
```

这段结果说明：
- `students[index]` 先被翻译成数组下标访问。
- 访问结果作为实参传给 `readStudent`。
- 报告里的 `Function Segment: readStudentArray` 能看到 `call 0` 和 `return`。

如果老师问“函数调用是不是调用地址”，可以这样答：

> 当前实现里不是机器级调用地址，而是通过函数表里的 FunctionRecord 生成 `call 函数编号` 形式的中间命令。函数体单独存放在 Function Segment 中，调用命令通过编号指向对应函数段。

### 8.2 结构体部分怎么介绍

结构体部分也不要只说“能声明结构体”，要讲到字段表和偏移。

我做的结构体链路包括：
- 支持顶层 `struct` 声明。
- 收集结构体字段。
- 检查字段是否重名。
- 检查字段类型是否合法。
- 为字段分配偏移量。
- 支持 `new StructName()` 实例化。
- 支持 `obj.field` 成员访问。
- 支持结构体引用赋值为 `null`。

结构体最关键的结果不是“字段名能识别”，而是：

> 成员访问最终会从字段名转换成偏移访问。

比如：

```text
struct Student {
    boolean gender;
}
a.gender = true;
```

报告里结构体表会显示：

```text
index=0 name=Student
  offset=0 type=boolean name=gender
```

命令里会出现类似：

```text
load_st_ref_address 0
bias_from_st_top_to_ref_boolean 0
load_st_boolean_static true
assign_from_st_top_to_ref_boolean
```

这说明：
- 先加载结构体变量 `a` 的引用。
- 再通过字段偏移 `0` 找到 `gender`。
- 最后把 `true` 写到这个字段位置。

如果老师问“结构体字段怎么访问”，可以这样答：

> 不是运行时按字符串字段名查找，而是在语义阶段把字段登记到结构体表里，同时分配 offset。生成中间命令时，成员访问会变成对象引用加字段偏移。

### 8.3 数组部分怎么介绍

数组部分重点要讲清楚两个点：数组类型和数组创建不是一回事。

我做的数组链路包括：
- 支持数组类型，例如 `Student[]`、`Student[][]`。
- 数组类型由元素类型和维度共同决定，不和创建时长度绑定。
- 支持 `new Type[expr]` 创建数组。
- 支持部分尾维为空，例如 `new Student[1][]`，为锯齿数组留下空间。
- 支持数组下标访问 `arr[index]`。
- 检查被下标访问的对象必须是数组。
- 检查下标表达式必须是 `int32`。

这里“显式维度表达式”指的是 `new` 数组时方括号里实际写出来的长度：

```text
new Student[1][2]
```

这里显式维度是两个：`1` 和 `2`。

```text
new Student[1][]
```

这里总维度是两个，但显式维度只有一个：`1`。

数组访问最关键的是：

> `arr[i]` 生成的不是普通值，而是数组元素的引用位置。

这样它才能既能出现在右边：

```text
x = arr[i];
```

也能出现在左边：

```text
arr[i] = x;
```

如果老师问“数组下标怎么生成命令”，可以这样答：

> 数组访问会先生成数组对象和下标表达式的命令，然后检查左侧是否是数组、下标是否是 int32，最后生成 `bias_from_st_top_to_ref_xxx` 这样的偏移访问命令，把数组引用偏移到元素引用。

### 8.4 三块怎么组合起来讲

最后不要分散收尾，要强调它们是能组合的。

可以用 `text50` 总结：

```text
boolean readStudentArray(Student[] students, int32 index) {
    return readStudent(students[index]);
}
```

这一个例子同时覆盖：
- 函数：`readStudentArray` 调用 `readStudent`。
- 结构体：数组元素类型是 `Student`。
- 数组：`students[index]` 访问数组元素。
- 返回：把函数调用结果作为返回值。

也可以用 `text49` 总结：


这一个例子同时覆盖：
- 多层结构体成员访问。
- 多层数组下标访问。
- 深层左值赋值。

#### 问题一：函数、结构体、数组是怎么定义的？

函数的定义：
- 函数由函数头和函数体组成。
- 函数头包括返回类型、函数名和参数列表。
- 返回类型可以是普通类型，也可以是 `void`。
- 参数必须有类型和名称。
- 函数体是一个代码块，但是函数定义本身只允许出现在顶层。

可以举例：

```text
boolean readStudent(Student s) {
    return s.gender;
}
```

这表示定义了一个返回 `boolean` 的函数，函数名是 `readStudent`，参数是一个 `Student` 类型的 `s`。

结构体的定义：
- 结构体用 `struct` 定义。
- 结构体内部是字段列表。
- 每个字段都有类型和字段名。
- 字段暂时不支持显式初始化，但是有默认值。
- 数字默认是 `0`，`boolean` 默认是 `false`，结构体和数组引用默认是 `null`。

可以举例：

```text
struct Student {
    boolean gender;
}
```

这表示定义了一个结构体类型 `Student`，里面有一个布尔字段 `gender`。

数组的定义：
- 数组类型通过 `[]` 表示维度。
- 数组类型由元素类型和维度共同组成，不把长度当成类型的一部分。
- `Student[]` 表示一维 `Student` 数组。
- `Student[][]` 表示二维 `Student` 数组。
- 数组创建时才写长度，例如 `new Student[2]`。
- 数组支持尾部空维度，例如 `new Student[1][]`，用于表达锯齿数组。

可以举例：

```text
Student[] direct;
Student[][] groups;
direct = new Student[2];
groups = new Student[1][2];
```

这表示 `direct` 是一维 `Student` 数组，`groups` 是二维 `Student` 数组，长度只在 `new` 的时候出现，不属于类型本身。

### 8.7 文法改动和翻译接入怎么对应

如果老师想追问“你到底改了哪些文法，后面怎么接到翻译器上”，可以直接按这条线讲。

#### 函数文法怎么改

函数相关文法主要包括：
- `function_decl ::= function_head block`
- `function_head ::= type id ( param_list ) | void id ( param_list )`
- `param_list ::= params | ε`
- `params ::= params , param | param`
- `param ::= type id`
- `return_stmt ::= return bool ; | return ;`
- `call_expr ::= id ( arg_list )`

这些文法改动的作用是：
- 让函数声明、参数列表、返回语句、函数调用都变成明确的语法结构。
- 让顶层函数定义和函数体代码块分开。

对应翻译器是：
- `FunctionHeadTranslator`：接收函数头的语法结果，准备函数签名。
- `FunctionDefinitionTranslator`：把函数体单独收集成 Function Segment。
- `FunctionCallTranslator`：把函数调用翻译成 `call` 命令。
- `FunctionReturnTranslator`：把 `return` 翻译成返回命令。

#### 结构体文法怎么改

结构体相关文法主要包括：
- `struct_decl ::= struct id { struct_field_list }`
- `struct_field_list ::= struct_fields | ε`
- `struct_fields ::= struct_fields struct_field | struct_field`
- `struct_field ::= type id ;`
- `new_struct_expr ::= new type_identifier ( )`
- `loc ::= loc . id | ...`

这些文法改动的作用是：
- 让结构体声明有独立入口。
- 让字段列表可以连续展开。
- 让结构体实例化必须显式写类型名。
- 让成员访问 `obj.field` 成为可识别的左值/表达式链路。

对应翻译器是：
- `StructSemanticCallback`：收集结构体字段并建立结构体表。
- `NewStructTranslator`：把 `new StructName()` 翻译成 `new_struct`。
- `MemberAccessTranslator`：把 `obj.field` 翻译成偏移访问命令。

#### 数组文法怎么改

数组相关文法主要包括：
- `type ::= type [ ] | ...`
- `new_array_expr ::= new array_creation_base array_creation_dims`
- `array_creation_base ::= type_identifier | boolean | character | int32 | float64 | string`
- `array_creation_dims ::= array_creation_dims array_creation_dim | array_creation_dim`
- `array_creation_dim ::= [ bool ] | [ ]`
- `loc ::= loc [ bool ] | ...`

这些文法改动的作用是：
- 让数组类型可以写成多维形式。
- 让数组创建时可以写完整维度，也可以留空尾维。
- 让数组下标访问 `arr[index]` 作为统一的访问形式进入语法树。

对应翻译器是：
- `ArrayTypeTranslator`：把数组类型节点接入类型系统。
- `NewArrayTranslator`：把数组创建翻译成 `new_array`。
- `ArrayAtExpressionTranslator`：把数组下标访问翻译成偏移访问命令。

#### 文法和翻译的关系怎么讲

你可以直接这样总结：

> 我先在 `grammar0.txt` 和 `ProgramSyntaxDemo.java` 里把函数、结构体、数组的文法规则补出来，再通过 `TagStrategyCompose` 把这些语法标签映射到对应的 translator。这样语法树一旦归约成 `FUNCTION`、`STRUCT_DECL`、`NEW_ARRAY`、`ACCESS` 这些标签，就会自动进入对应的语义检查和命令翻译流程。

如果老师继续追问“这是不是只改文法”，你就答：

> 不是，只改文法不够。我还把这些文法接到了语义回调和命令翻译器上，最终让函数、结构体、数组能够进入报告里的命令输出和测试验证。
