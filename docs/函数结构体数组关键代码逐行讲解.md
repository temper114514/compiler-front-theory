# 函数、结构体与数组关键代码逐行讲解

本文用于讲解我负责的语义分析后半部分：函数、结构体、数组，以及它们对应的中间代码生成。

这几块代码的共同特点是：它们不是只判断语法形状是否正确，而是把语法树上的结构转换成可检查、可生成中间代码的语义信息。

整体链路如下：

```text
源码
  -> 词法分析：切成 token
  -> 语法分析：归约成语法树节点
  -> 语义分析：注册函数表、结构体表，检查类型和 return
  -> 中间代码生成：生成 call、new_array、成员偏移访问等命令
```

---

## 1. 函数语义检查：FunctionSemanticCallback

对应文件：

```text
src/main/java/org/harvey/vie/theory/semantic/function/FunctionSemanticCallback.java
```

这个类负责函数相关的三件事：

```text
1. 函数声明注册
2. return 语句检查
3. 函数调用检查
```

### 1.1 类声明与动作分派

关键代码：

```java
public class FunctionSemanticCallback implements ShiftReduceCallback {
    private static final ProductionTagStrategy<ReduceAction> REDUCE_ACTIONS = new ProductionTagStrategy<>(ReduceAction.NOOP)
            .when(ReduceAction.PREPARE_FUNCTION, ProgramSemanticTag.FUNCTION, ProgramSemanticTag.HEAD)
            .when(ReduceAction.VALIDATE_RETURN, ProgramSemanticTag.RETURN)
            .when(ReduceAction.VALIDATE_CALL, ProgramSemanticTag.FUNCTION, ProgramSemanticTag.CALL);
```

逐行解释：

```text
FunctionSemanticCallback implements ShiftReduceCallback
```

表示这个类会接入自底向上的 shift-reduce 语法分析过程。每当语法分析完成一次归约，就有机会触发这里的语义动作。

```text
ProductionTagStrategy<ReduceAction>
```

表示不直接用字符串判断产生式，而是用产生式上的语义标签来选择动作。

```text
FUNCTION + HEAD -> PREPARE_FUNCTION
```

当归约出函数头时，执行函数声明注册。

```text
RETURN -> VALIDATE_RETURN
```

当归约出 return 语句时，执行 return 合法性检查。

```text
FUNCTION + CALL -> VALIDATE_CALL
```

当归约出函数调用表达式时，检查函数调用是否合法。

讲解时可以说：

```text
这里没有通过字符串硬编码产生式，而是通过语义标签分派动作。
这样函数声明、return、函数调用可以各自对应不同的语义处理。
```

### 1.2 onReduce：每次归约后的入口

关键代码：

```java
@Override
public void onReduce(ShiftReduceSemanticContext context, SimpleGrammarProduction production) {
    onReduce0(context, production);
    ShiftReduceCallback.super.onReduce(context, production);
}
```

逐行解释：

```text
onReduce(...)
```

是 shift-reduce 分析过程中“完成一次归约”时触发的回调。

```text
onReduce0(context, production)
```

先执行本类自己的函数语义逻辑。

```text
ShiftReduceCallback.super.onReduce(...)
```

再保留默认回调行为，避免破坏回调链。

讲解时可以说：

```text
函数语义检查不是单独跑一遍语法树，而是在归约过程中同步触发。
这样每个语法节点刚归约出来，就可以马上建立或检查它的语义信息。
```

### 1.3 onReduce0：根据标签选择语义动作

关键代码：

```java
private void onReduce0(ShiftReduceSemanticContext context, SimpleGrammarProduction production) {
    if (context.getTreeContext().isEmpty() || !context.getTreeContext().peek().isHead()) {
        return;
    }
    HeadNode head = context.getTreeContext().peek().toHead();
    REDUCE_ACTIONS.resolve(production).accept(this, context, head);
}
```

逐行解释：

```text
context.getTreeContext()
```

表示当前已经构造出来的语法树节点栈。

```text
isEmpty()
```

如果当前没有语法树节点，就没有东西可以处理，直接返回。

```text
!peek().isHead()
```

如果栈顶不是非终结符节点，也不处理。函数声明、return、调用这些结构都应该是规约后的 HeadNode。

```text

```

取出当前刚归约出来的语法树头节点。

```text

```

根据当前产生式的语义标签查找应该执行的动作。

```text

```

真正执行这个动作，比如注册函数、检查 return、检查调用。

讲解时可以说：

```text
这里是函数语义检查的分发中心。它先确认当前节点是一个完整语法结构，再根据标签选择对应的函数语义动作。
```

### 1.4 prepareFunction：注册函数声明

关键代码：

```java
private void prepareFunction(ShiftReduceSemanticContext context, HeadNode head) {
    SourceToken nameToken = tokenAt(head, 1);
    if (context.existFunction(nameToken)) {
        SemanticDiagnostics.reject(context, nameToken, "duplicate function declaration is not allowed.");
    }
    TypeRegister returnTypeRegister = resolveReturnType(context, head);
    if (returnTypeRegister == null) {
        throw new CompilerException("function return type is missing.");
    }
    SemanticType returnType = returnTypeRegister.requireType("function return type is required.");
    List<FunctionParameter> parameters = collectParameters(context, head.get(3));
    FunctionRecord record = new FunctionRecord(
            context.functionTableSize(),
            new FunctionSignature(nameToken, returnType, head),
            parameters,
            head
    );
    context.registerFunction(record);
    context.markPendingFunction(record);
}
```

逐行解释：

```text

```

例如：

```text

      ^^^
      这里就是 nameToken
```

```text

```

检查函数表里是否已经有同名函数。


### 1.5 collectParameters：收集形参列表

关键代码：

```java
private List<FunctionParameter> collectParameters(
        ShiftReduceSemanticContext context, ShiftReduceSyntaxTreeNode node) {
    List<FunctionParameter> result = new ArrayList<>();
    SyntaxTreeListIterator<HeadNode> iterator = new SyntaxTreeListIterator<>(node, parameterStepper);
    while (iterator.hasNext()) {
        HeadNode head = iterator.next();
        TypeRegister register = context.getType(head.get(0));
        if (register == null) {
            throw new CompilerException("parameter type is missing.");
        }
        SemanticType type = register.requireType("parameter type is required.");
        SourceToken nameToken = tokenAt(head, 1);
        SemanticDiagnostics.requireNotVoid(context, type, nameToken, "void cannot be used as parameter type.");
        for (FunctionParameter parameter : result) {
            if (parameter.isNamed(nameToken)) {
                SemanticDiagnostics.reject(context, nameToken, "duplicate parameter declaration is not allowed.");
            }
        }
        result.add(new FunctionParameter(nameToken, type, head.get(0).toHead()));
    }
    return result;
}
```

逐行解释：

```text
List<FunctionParameter> result
```

创建结果列表，用来保存参数。

```text
SyntaxTreeListIterator
```

参数列表在语法树里通常是链式结构，比如：

```text
params -> params , param
params -> param
```

这个迭代器负责把链式语法树展开成顺序列表。

```text
context.getType(head.get(0))
```

读取参数类型。参数节点第 0 个子节点是类型。

```text
register.requireType(...)
```

取出参数类型。

```text
SourceToken nameToken = tokenAt(head, 1)
```

取出参数名。

```text
requireNotVoid(...)
```

禁止参数类型为 void。

```text
for (FunctionParameter parameter : result)
```

遍历已经收集过的参数。

```text
parameter.isNamed(nameToken)
```

检查是否存在重名参数。

```text
result.add(new FunctionParameter(...))
```

把参数加入结果列表。

讲解时可以说：

```text
参数表不是简单保存字符串，而是按源码顺序保存“参数名 + 参数类型”。
这样函数调用时才能按位置比较实参和形参。
```

### 1.6 validateCall：检查函数调用

关键代码：

```java
private void validateCall(ShiftReduceSemanticContext context, HeadNode head) {
    SourceToken nameToken = tokenAt(head, 0);
    FunctionRecord record = context.getFunction(nameToken);
    if (record == null) {
        SemanticDiagnostics.reject(context, nameToken, "function must be defined before it is called.");
        return;
    }
    List<TypeRegister> args = collectArgumentTypes(context, head.get(2));
    if (args.size() != record.getParameters().size()) {
        SemanticDiagnostics.reject(context, nameToken, "function argument count does not match.");
    }
    for (int i = 0; i < args.size(); i++) {
        SemanticType sourceType = args.get(i).requireType("argument type is required.");
        SemanticType targetType = record.getParameters().get(i).getType();
        SemanticDiagnostics.requireAssignable(context,
                sourceType,
                targetType,
                nameToken,
                "function argument type does not match parameter type."
        );
    }
}
```

逐行解释：

```text
tokenAt(head, 0)
```

函数调用节点第 0 个子节点是函数名。

```text
context.getFunction(nameToken)
```

从函数表中查找被调用函数。

```text
record == null
```

如果找不到函数，说明调用了未声明函数。

```text
collectArgumentTypes(context, head.get(2))
```

收集实参表达式的类型。函数调用中第 2 个子节点是实参列表。

```text
args.size() != record.getParameters().size()
```

检查实参数量和形参数量是否一致。

```text
sourceType
```

实参类型。

```text
targetType
```

对应形参类型。

```text
requireAssignable(...)
```

检查实参类型能不能赋给形参类型。

讲解时可以说：

```text
函数调用不是只看函数名是否存在，还要检查实参与形参的数量和类型是否匹配。
```

### 1.7 validateReturnValue：检查 return 语句

关键代码：

```java
private void validateReturnValue(ShiftReduceSemanticContext context, HeadNode head, boolean hasValue) {
    SourceToken returnToken = tokenAt(head, 0);
    if (!context.insideFunction()) {
        SemanticDiagnostics.reject(context, returnToken, "return is only allowed inside function body.");
    }
    SemanticType returnType = context.currentFunctionReturnType();
    if (returnType == null) {
        throw new CompilerException("current function return type is missing.");
    }
    if (!hasValue) {
        if (!returnType.isVoidScalar()) {
            SemanticDiagnostics.reject(context, returnToken, "non-void function must return a value.");
        }
        return;
    }
    if (returnType.isVoidScalar()) {
        SemanticDiagnostics.reject(context, returnToken, "void function cannot return a value.");
    }
    TypeRegister valueType = context.getType(head.get(1));
    if (valueType == null) {
        throw new CompilerException("return value type is missing.");
    }
    SemanticDiagnostics.requireAssignable(context,
            valueType.requireType("return value type is required."),
            returnType,
            returnToken,
            "return value type does not match function return type."
    );
}
```

逐行解释：

```text
returnToken
```

取出 return 关键字，用来定位错误位置。

```text
!context.insideFunction()
```

检查 return 是否出现在函数内部。

```text
context.currentFunctionReturnType()
```

获取当前所在函数的返回类型。

```text
!hasValue
```

表示当前 return 是 `return;`，没有返回值。

```text
!returnType.isVoidScalar()
```

如果当前函数不是 void，但 return 没有值，就报错。

```text
returnType.isVoidScalar()
```

如果当前函数是 void，但 return 后面带了值，也报错。

```text
context.getType(head.get(1))
```

获取 return 后面表达式的类型。

```text
requireAssignable(...)
```

检查返回值类型是否能赋给函数返回类型。

讲解时可以说：

```text
return 检查分为语句级检查和控制流检查。
这里负责语句级检查：return 是否在函数内，是否带值，返回值类型是否正确。
```

## 2. 函数 return 控制流分析：FunctionReturnFlowAnalyzer

对应文件：

```text
src/main/java/org/harvey/vie/theory/semantic/function/FunctionReturnFlowAnalyzer.java
```

这个类解决的问题是：

```text
非 void 函数不是“出现过 return”就一定正确，
而是必须保证所有可达执行路径都能 return。
```

### 2.1 规则表

关键代码：

```java
rules = new ProductionTagStrategy<>(never)
        .when(block, ProgramSemanticTag.BLOCK, ProgramSemanticTag.COMMAND)
        .when(never, ProgramSemanticTag.BLOCK, ProgramSemanticTag.LIST, ProgramSemanticTag.EMPTY)
        .when(blockItemsSequence, ProgramSemanticTag.BLOCK, ProgramSemanticTag.LIST, ProgramSemanticTag.SEQUENCE)
        .when(forward, ProgramSemanticTag.FORWARD)
        .when(returnRule, ProgramSemanticTag.RETURN)
        .when(matchIf, ProgramSemanticTag.CONDITIONAL, ProgramSemanticTag.ELSE_BRANCH);
```

逐行解释：

```text
new ProductionTagStrategy<>(never)
```

默认规则是不保证返回。

```text
BLOCK + COMMAND -> block
```

代码块交给 block 规则判断。

```text
BLOCK + LIST + EMPTY -> never
```

空语句列表肯定不保证返回。

```text
BLOCK + LIST + SEQUENCE -> blockItemsSequence
```

语句序列交给顺序规则判断。

```text
FORWARD -> forward
```

转发节点继续检查子节点。

```text
RETURN -> returnRule
```

return 语句本身保证返回。

```text
CONDITIONAL + ELSE_BRANCH -> matchIf
```

带 else 的 if 需要分析两个分支。

讲解时可以说：

```text
这里也是用语义标签分派规则，而不是写死产生式字符串。
每类语法结构对应一种“是否保证返回”的判断规则。
```

### 2.2 guaranteesReturn：入口方法

关键代码：

```java
public boolean guaranteesReturn(ShiftReduceSemanticContext context, ShiftReduceSyntaxTreeNode node) {
    if (node == null || !node.isHead()) {
        return false;
    }
    HeadNode head = node.toHead();
    return rules.resolve(head.getProduction()).test(context, head);
}
```

逐行解释：

```text
node == null
```

没有节点，不可能保证返回。

```text
!node.isHead()
```

不是语法树头节点，也无法按产生式分析，返回 false。

```text
HeadNode head = node.toHead()
```

转换成可分析的语法树头节点。

```text
rules.resolve(head.getProduction())
```

根据这个节点对应的产生式找到规则。

```text
test(context, head)
```

执行规则，返回是否保证 return。

### 2.3 blockItemsSequenceGuaranteesReturn：顺序语句分析

关键代码：

```java
public boolean blockItemsSequenceGuaranteesReturn(
        ShiftReduceSemanticContext context, HeadNode head) {
    return guaranteesReturn(context, head.get(0)) || guaranteesReturn(context, head.get(1));
}
```

逐行解释：

```text
head.get(0)
```

语句序列前半段。

```text
head.get(1)
```

语句序列后半段。

```text
左边 || 右边
```

只要前面已经保证返回，那么后面不可达，整个序列就保证返回。

如果前面不保证返回，就继续看后面是否保证返回。

讲解时可以说：

```text
顺序语句里，只要某个前置语句已经保证 return，后面的语句即使存在也不可达。
因此这里用“前半段保证返回 或 后半段保证返回”。
```

### 2.4 matchedIfGuaranteesReturn：if-else 返回分析

关键代码：

```java
public boolean matchedIfGuaranteesReturn(ShiftReduceSemanticContext context, HeadNode head) {
    Boolean condition = constantBoolean(context, head.get(2));
    if (Boolean.TRUE.equals(condition)) {
        return guaranteesReturn(context, head.get(4));
    }
    if (Boolean.FALSE.equals(condition)) {
        return guaranteesReturn(context, head.get(6));
    }
    return guaranteesReturn(context, head.get(4)) && guaranteesReturn(context, head.get(6));
}
```

逐行解释：

```text
constantBoolean(context, head.get(2))
```

尝试读取 if 条件的编译期常量值。

```text
Boolean.TRUE.equals(condition)
```

如果条件恒为 true，只检查 then 分支。

```text
head.get(4)
```

then 分支。

```text
Boolean.FALSE.equals(condition)
```

如果条件恒为 false，只检查 else 分支。

```text
head.get(6)
```

else 分支。

```text
then && else
```

如果条件无法确定，那么两个分支都必须保证返回。

讲解时可以说：

```text
对于 if-else，如果条件不是编译期常量，就必须要求 then 和 else 两条路径都 return。
如果条件已经折叠为 true 或 false，就只检查实际可达的分支。
```

### 3.2 function：查找被调函数

关键代码：

```java
private FunctionRecord function(ShiftReduceSemanticContext context) {
    if (context.getTreeContext().isEmpty() || !context.getTreeContext().peek().isHead()) {
        throw new CompilerException("current reduced head is absent for function call.");
    }
    HeadNode head = context.getTreeContext().peek().toHead();
    ShiftReduceSyntaxTreeNode tokenNode = head.get(0);
    if (!tokenNode.isToken()) {
        throw new CompilerException("function call name is absent.");
    }
    FunctionRecord record = context.getFunction(tokenNode.toToken().getSource());
    if (record == null) {
        throw new CompilerException("function is not declared in current visible scope.");
    }
    return record;
}
```

逐行解释：

```text
检查 treeContext 是否为空
```

如果没有当前归约节点，说明翻译阶段上下文异常。

```text
peek().isHead()
```

函数调用应该是一个完整的 HeadNode。

```text
head.get(0)
```

函数调用节点第 0 个子节点是函数名。

```text
!tokenNode.isToken()
```

如果函数名不是 token，说明语法树形状异常。

```text
context.getFunction(...)
```

根据函数名到函数表中取函数记录。

```text
record == null
```

讲解时可以说：

```text

```

### 4.1 结构体动作分派

### 4.3 collectFields：收集字段并分配偏移

关键代码：

```java
private List<StructField> collectFields(ShiftReduceSemanticContext context, HeadNode listHead) {
    List<StructField> fields = new ArrayList<>();
    SyntaxTreeListIterator<HeadNode> iterator = new SyntaxTreeListIterator<>(listHead, fieldStepper);
    int offset = 0;
    while (iterator.hasNext()) {
        HeadNode fieldHead = iterator.next();
        TypeRegister register = context.getType(fieldHead.get(0));
        if (register == null) {
            throw new IllegalStateException("struct field type is missing.");
        }
        SemanticType type = register.requireType("struct field type is required.");
        SourceToken fieldName = fieldHead.get(1).toToken().getSource();
        SemanticDiagnostics.requireNotVoid(context, type, fieldName, "void cannot be used as struct field type.");
        for (StructField field : fields) {
            if (field.isNamed(fieldName)) {
                SemanticDiagnostics.reject(context, fieldName, "duplicate struct field declaration is not allowed.");
            }
        }
        fields.add(new StructField(fieldName, type, offset++));
    }
    return fields;
}
```

```java
public CommandNodeRegister translate(
        ShiftReduceSemanticContext context,
        SimpleGrammarProduction production,
        CommandNodeRegister[] children) {
    SemanticType type = TypeAttributes.childType(context, 1);
    SemanticDiagnostics.requireNotVoid(
            context,
            type,
            TypeAttributes.childAnchor(context, 1),
            "void cannot be used as array element type."
```

### 6.1 translate：成员访问翻译

关键代码：

```java
public CommandNodeRegister translate(
        ShiftReduceSemanticContext context,
        SimpleGrammarProduction production,
        CommandNodeRegister[] children) {
    CommandNodeBuilder builder = new CommandNodeListBuilder();
    children[0].register(builder);
    SemanticType baseType = TypeAttributes.childType(context, 0);
    if (baseType == null) {
        SemanticDiagnostics.reject(
                context,
                TypeAttributes.childAnchor(context, 0),
                "member access requires a typed left operand."
        );
    }
    StructRecord struct = context.getStruct(baseType);
    if (struct == null) {
        SemanticDiagnostics.reject(
                context,
                TypeAttributes.childAnchor(context, 0),
                "member access requires a declared struct operand."
        );
    }
    StructField field = struct.field(TypeAttributes.childAnchor(context, 2));
    builder.add(new TerminalNode(context.getCommandFactory().biasFromStTopToRef(
            CommandDataType.forStorage(field.getType()),
            field.getOffset()
    )));
    return new NormalCommandNodeRegister(builder.build(), production, children);
}
```

逐行解释：




```text

```


## 7. 汇报时的整体讲法

可以按下面顺序讲：

```text
第一，我负责函数。
函数声明时注册函数表，调用时查函数表并检查实参与形参，return 时检查返回位置、返回形式、返回类型。
对于非 void 函数，还要做控制流分析，判断所有可达路径是否都能 return。

第二，我负责结构体。
结构体声明时注册结构体表，收集字段列表并分配字段偏移。
成员访问时先检查左边是不是结构体，再查字段是否存在，最后在中间代码里转换成基址加偏移。

第三，我负责数组。
数组创建时检查元素类型，汇总维度信息，先生成长度表达式求值代码，再生成数组分配指令。
数组类型由元素类型和维度组成，长度不属于类型，所以支持锯齿数组。
```

最后总结：

```text
这部分代码的重点不是“能不能解析出函数、结构体、数组”，而是把它们接入语义表、类型检查和中间代码生成。
函数依赖函数表，结构体依赖结构体表，数组依赖维度信息和元素类型。
```
